# Agent handbook

Nest Panel is an independent single-user Go/Vue application. One container, one `/data` volume, SQLite. Do not add registration, external database, public image gallery or LAN/WAN switching. Keep private navigation and all administrator endpoints authenticated when public access is off. Public mode exposes visible groups and their links. Hidden groups and their exclusive icons require authentication. Account hashes, sessions, exports, backups and Docker metadata remain private.

Read README before modifying. Persist configuration atomically, keep revision conflict detection, and preserve existing volumes. Credentials use bcrypt; sessions expire after a fixed seven days and survive restart, but password change and full restore revoke every session. Ordinary JSON exports contain portable Base64 images but no account credentials; complete backups use password-based authenticated encryption. Never commit local data, secrets or private screenshots.

Website metadata fetches intentionally permit administrator-specified RFC1918 addresses but block loopback, link-local and metadata addresses, revalidate redirects and DNS at dial time, do not use proxy environment variables, and never return raw HTML or upstream errors. Rasterize/re-encode images before serving. Docker integration only calls GET containers/json on the configured local Unix socket. Read-only bind mounts do not make Docker APIs read-only; never implement mutations or expose raw container labels/environment to guests.

Category position, website style and black/white overlay are independently selectable. The horizontal style stores the cards layout with glass icon presentation. Preserve the legacy theme fields for backup compatibility; background/opacity/blur are included in both export and backup. Avoid idle polling, large UI frameworks, animated wallpapers, or embedding every Base64 icon in public responses. Build the frontend before the Go binary. Run Go tests/vet and Linux race tests, inspect UI with the authorized in-app browser, build/run a local image, measure idle/representative load, then publish versioned amd64/arm64 and latest tags and GitHub Release. Only after successful release update the user's Wiki with home/navigation entries. No Sites deployment is required.
